Create JPA entities that map exactly to the existing Flyway-managed schema (V1__init_schema.sql).

**AppUser.java** in `user.internal`:
- `@Entity` `@Table(name = "app_user")`
- Fields mapping to columns: id (BIGINT IDENTITY), email (VARCHAR 255, unique, not null), username (VARCHAR 100, unique, not null), passwordHash (VARCHAR 255, `@Column(name = "password_hash")`, not null), firstName (VARCHAR 100, `@Column(name = "first_name")`), lastName (VARCHAR 100, `@Column(name = "last_name")`), enabled (BOOLEAN, default false), emailVerified (BOOLEAN, `@Column(name = "email_verified")`, default false), createdAt (LocalDateTime, `@Column(name = "created_at")`, not null, updatable=false), updatedAt (LocalDateTime, `@Column(name = "updated_at")`, not null)
- `@Id` `@GeneratedValue(strategy = GenerationType.IDENTITY)` for id
- `@ManyToMany(fetch = FetchType.EAGER)` `@JoinTable(name = "user_role", joinColumns = @JoinColumn(name = "user_id"), inverseJoinColumns = @JoinColumn(name = "role_id"))` for roles (Set of AppRole)
- `@PrePersist` sets createdAt and updatedAt to LocalDateTime.now()
- `@PreUpdate` sets updatedAt to LocalDateTime.now()
- Protected no-arg constructor (JPA requirement)
- Public constructor for creating new users (email, username, passwordHash)
- Getters and setters for all fields
- `equals()` and `hashCode()` by id only (null-safe)
- `addRole(AppRole role)` convenience method

**AppRole.java** in `user.internal`:
- `@Entity` `@Table(name = "app_role")`
- Fields: id (BIGINT IDENTITY), name (VARCHAR 50, unique, not null)
- Protected no-arg constructor, public constructor taking name
- Getters only (roles are immutable after creation)
- `equals()` and `hashCode()` by id only

**Important:** Use `GenerationType.IDENTITY` (matches GENERATED BY DEFAULT AS IDENTITY in Flyway schema). Do NOT use `GenerationType.AUTO` or `GenerationType.SEQUENCE` -- H2 in PostgreSQL mode requires IDENTITY.

- `Optional<AppUser> findByEmail(String email)`
- `Optional<AppUser> findByUsername(String username)`
- `boolean existsByEmail(String email)`

**RoleRepository.java** in `user.internal`:
- `interface RoleRepository extends JpaRepository<AppRole, Long>`
- `Optional<AppRole> findByName(String name)`

**UserDto.java** in `shared.dto` (new subpackage):
- Java record: `public record UserDto(Long id, String email, String username, String firstName, String lastName, boolean enabled, boolean emailVerified, Set<String> roles)`
- Static factory method: `public static UserDto from(...)` -- takes the same fields and constructs the record. This will be called from UserService to convert from internal entity to public DTO. Accept individual field values (not the entity itself) to avoid leaking the entity type across module boundaries.

**UserService.java** in `user` package root (public API of user module):
- `@Service` annotation
- Inject `UserRepository` and `RoleRepository`
- `public Optional<UserDto> getUserByEmail(String email)` -- finds user by email, converts to UserDto
- `public UserDto createUser(String email, String username, String passwordHash, String firstName, String lastName)` -- creates new user with default ROLE_USER, enabled=true, returns UserDto. Fetches ROLE_USER from RoleRepository (throw IllegalStateException if role not found -- it should always exist from Flyway seed). Sets enabled=true because email verification will disable it in Phase 4.
- `public boolean existsByEmail(String email)` -- delegates to repository
- Internal helper: convert AppUser entity to UserDto (private method)

**Important:** UserService is in the `user` package root (not `user.internal`) because it is the module's public API. Repositories and entities stay in `user.internal` (not accessible from other modules per Spring Modulith).

**Important:** The `getUserByEmail` method must also return the passwordHash and roles for authentication. Add a separate method or a richer return type. Better approach: add `public Optional<UserAuthDto> getUserAuthDetailsByEmail(String email)` that returns email, passwordHash, enabled, and role names. Create a `UserAuthDto` record in `user` package: `public record UserAuthDto(String email, String passwordHash, boolean enabled, boolean emailVerified, Set<String> roles)`. This keeps the auth-specific data separate from the general UserDto.

Wait -- Spring Modulith: the auth module has `allowedDependencies = { "user", "shared" }`. So auth CAN call user's public API. UserService exposes the public API.
