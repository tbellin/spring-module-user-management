  <action>
    Create Flyway migration to add `password_changed_at TIMESTAMP` column to `app_user` table.

    PostgreSQL migration is V2 (only V1 exists in postgresql/).
    H2 migration is V3 (V1 is schema, V2 is seed data in h2/).

    Both files contain the same SQL:
    ```sql
    ALTER TABLE app_user ADD COLUMN password_changed_at TIMESTAMP;
    ```

    The column is nullable -- existing users have no password change history. No default value needed.

    Also add the `passwordChangedAt` field to AppUser entity:
    - Add field: `@Column(name = "password_changed_at") private LocalDateTime passwordChangedAt;`
    - Add getter: `public LocalDateTime getPasswordChangedAt() { return passwordChangedAt; }`
    - Add setter: `public void setPasswordChangedAt(LocalDateTime passwordChangedAt) { this.passwordChangedAt = passwordChangedAt; }`
    - Place the field after the `updatedAt` field, before the `@ManyToMany` roles field.
    - Do NOT add it to the constructor -- it's optional and set only on password changes.
  </action>
  <verify>Run `./mvnw compile -q` to confirm no compilation errors. Check that the migration files exist and contain the correct SQL.</verify>

<task type="auto">
  <name>Task 2: PasswordResetToken entity, repository, and sealed result</name>
  <files>
    src/main/java/com/example/usermanagement/auth/internal/password/PasswordResetToken.java
    src/main/java/com/example/usermanagement/auth/internal/password/PasswordResetTokenRepository.java

  <action>
    Create the `auth/internal/password/` package with three files, following the Phase 4 verification token pattern exactly.

    **PasswordResetToken.java** -- Copy the structure of VerificationToken.java exactly:
    - `@Entity @Table(name = "password_reset_token")`
    - Fields: id (Long, IDENTITY), token (String, unique), user (AppUser, @ManyToOne LAZY), expiryDate (LocalDateTime), used (boolean, default false), createdAt (LocalDateTime)
    - Protected no-arg constructor (JPA requirement)
    - Public constructor: `PasswordResetToken(String token, AppUser user, LocalDateTime expiryDate)`
    - `@PrePersist` sets createdAt
    - Methods: `isExpired()`, `isValid()`, all getters, `setUsed(boolean)`
    - `equals/hashCode` based on id only (same pattern as VerificationToken)
    - `toString()` truncates token to first 8 chars

    **PasswordResetTokenRepository.java** -- Copy VerificationTokenRepository pattern:
    - `extends JpaRepository<PasswordResetToken, Long>`
    - `Optional<PasswordResetToken> findByToken(String token)`
    - `@Modifying @Query("UPDATE PasswordResetToken t SET t.used = true WHERE t.token = :token AND t.used = false") int markAsUsed(@Param("token") String token)` -- atomic CAS for race condition prevention
    - `void deleteByUser(AppUser user)` -- cleanup all tokens for a user

    **PasswordResetResult.java** -- Sealed interface with 4 outcomes:
    - `record Success() implements PasswordResetResult {}` -- password was reset
    - `record Expired() implements PasswordResetResult {}` -- token expired
    - `record Invalid() implements PasswordResetResult {}` -- token not found
    - `record AlreadyUsed() implements PasswordResetResult {}` -- token already consumed

    Unlike VerificationResult which has 5 types (includes AlreadyVerified), PasswordResetResult has 4 types. There is no "AlreadyReset" equivalent because password reset is not an idempotent state.
  </action>
  <verify>Run `./mvnw compile -q` to confirm compilation. All three files should compile without errors and follow the exact patterns from the verification package.</verify>
  <done>PasswordResetToken entity maps to password_reset_token table. Repository has atomic markAsUsed. PasswordResetResult has 4 exhaustive outcome types. All compile cleanly.</done>
</task>

    Create three request DTO records in the `auth/internal/password/` package, following the established pattern from RegistrationRequest and ResendVerificationRequest.

    **ChangePasswordRequest.java** -- For authenticated password change (PASS-01):
    ```java
    public record ChangePasswordRequest(
        @NotBlank(message = "Current password is required")
        String currentPassword,

        @NotBlank(message = "New password is required")
        @Size(min = 8, message = "New password must be at least 8 characters")
        String newPassword,

        @NotBlank(message = "Password confirmation is required")
        String confirmPassword
    ) {}
    ```
    NOTE: REQUIREMENTS.md says "requires current password" -- 3 fields: current, new, confirm. This overrides CONTEXT.md which said 2 fields.

    **ForgotPasswordRequest.java** -- For requesting password reset email (PASS-02):
    ```java
    public record ForgotPasswordRequest(
        @NotBlank(message = "Email is required")
        @Email(message = "Please provide a valid email address")
        String email
    ) {}
    ```

    **ResetPasswordRequest.java** -- For setting new password via token (PASS-03):
    ```java
    public record ResetPasswordRequest(
        @NotBlank(message = "Token is required")
        String token,

        @NotBlank(message = "New password is required")
        @Size(min = 8, message = "New password must be at least 8 characters")
        String newPassword,

        @NotBlank(message = "Password confirmation is required")
        String confirmPassword
    ) {}
    ```

    All records use `jakarta.validation.constraints` annotations (`@NotBlank`, `@Email`, `@Size`).
