  <action>
    Create REST API controller in `auth/internal/password/` package following AuthController patterns.

    ```java
    @RestController
    @RequestMapping("/api/v1/auth")
    public class PasswordController {
        // Inject: PasswordService, ResendRateLimiter
    }
    ```

    **Endpoint 1: POST /api/v1/auth/change-password** (PASS-01 API)
    - Requires authentication (already enforced by SecurityConfig - anyRequest().authenticated() for non-public paths)
    - Accept `@Valid @RequestBody ChangePasswordRequest request`
    - Get authenticated user's email from `Authentication.getName()` (the principal username is the email)
    - Validate confirmPassword matches newPassword: if not, return 400 with error message
    - Call `passwordService.changePassword(email, request.currentPassword(), request.newPassword())`
    - On success: return 200 with `{"message": "Password changed successfully"}`
    - BadRequestException from service (wrong current password) propagates to GlobalExceptionHandler -> 400

    **Endpoint 2: POST /api/v1/auth/forgot-password** (PASS-02 API)
    - Public endpoint (already covered by `/api/v1/auth/**` permitAll in SecurityConfig)
    - Accept `@Valid @RequestBody ForgotPasswordRequest request`
    - Check rate limit: if `!rateLimiter.canResend(email)`, return 429 with retryAfter (same pattern as resend-verification)
    - Call `passwordService.requestPasswordReset(request.email())`
    - Always return 200 with `{"message": "If an account exists with this email, a password reset link has been sent"}` (SEC-01)

    **Endpoint 3: POST /api/v1/auth/reset-password** (PASS-03 API)
    - Public endpoint (covered by `/api/v1/auth/**` permitAll)
    - Accept `@Valid @RequestBody ResetPasswordRequest request`
    - Validate confirmPassword matches newPassword: if not, return 400
    - Call `passwordService.resetPassword(request.token(), request.newPassword())`
    - Switch on PasswordResetResult:
      - Success -> 200 `{"message": "Password has been reset successfully"}`
      - Expired -> 400 `{"message": "Reset link has expired. Please request a new one."}`
      - Invalid -> 400 `{"message": "Invalid reset link."}`
      - AlreadyUsed -> 400 `{"message": "This reset link has already been used."}`

    Use `ResponseEntity<Map<String, String>>` for responses (same pattern as AuthController resend-verification).
  </action>
  <verify>Run `./mvnw compile -q` to confirm compilation. PasswordController should have 3 endpoint methods.</verify>
  <done>REST API controller with 3 endpoints: change-password (authenticated), forgot-password (public, SEC-01, rate-limited), reset-password (public, token-based). All follow AuthController patterns.</done>

    **PasswordWebController.java** -- Create web controller following AuthWebController and EmailVerificationController patterns:

    ```java
    @Controller
    public class PasswordWebController {
        // Inject: PasswordService, ResendRateLimiter
    }
    ```

    **GET /change-password** -- Show change password form:
    - Requires authentication (enforced by SecurityConfig anyRequest().authenticated())
    - Return: `"auth/change-password"`

    **POST /change-password** -- Process change password form:
    - Requires authentication
    - Accept `@RequestParam String currentPassword, @RequestParam String newPassword, @RequestParam String confirmPassword`
    - Validate newPassword matches confirmPassword: if not, add `error` to model, return `"auth/change-password"`
    - Validate newPassword length >= 8: if not, add `error` to model, return `"auth/change-password"`
    - Call `passwordService.changePassword(authentication.getName(), currentPassword, newPassword)`
    - Catch `BadRequestException` (wrong current password): add `error` to model, return `"auth/change-password"`
    - On success: invalidate session and clear SecurityContext:
      ```java
      SecurityContextHolder.clearContext();
      HttpSession session = request.getSession(false);
      if (session != null) { session.invalidate(); }
      ```
    - Redirect to `/login` with flash attribute toast: `new Toast("success", "Password changed successfully. Please log in with your new password.")`
    - Method signature needs: `Authentication authentication, HttpServletRequest request, RedirectAttributes redirectAttributes, Model model`

    **GET /forgot-password** -- Show forgot password form:
    - Public (permitAll in SecurityConfig)
    - Return: `"auth/forgot-password"`

    **POST /forgot-password** -- Process forgot password request:
    - Public
    - Accept `@RequestParam String email`
    - Check rate limit: if not allowed, add `error` = "Please wait before requesting another reset email" to model
    - Otherwise: call `passwordService.requestPasswordReset(email)` and add `message` = "If an account exists with this email, we sent a reset link." to model
    - Always return `"auth/forgot-password"` (stay on same page with message, SEC-01)

    **GET /reset-password** -- Show reset password form:
    - Public (permitAll)
    - Accept `@RequestParam String token`
    - Add `token` to model so the form can include it as hidden field
    - Return: `"auth/reset-password"`

    **POST /reset-password** -- Process password reset:
    - Public
    - Accept `@RequestParam String token, @RequestParam String newPassword, @RequestParam String confirmPassword`
    - Validate newPassword matches confirmPassword: if not, add `error` and `token` to model, return `"auth/reset-password"`
    - Validate newPassword length >= 8: if not, add `error` and `token` to model, return `"auth/reset-password"`
    - Call `passwordService.resetPassword(token, newPassword)`
    - Switch on result:
      - Success -> return `"auth/reset-success"`
      - Expired -> add `error` = "This reset link has expired. Please request a new one." to model, return `"auth/reset-error"`
      - Invalid -> add `error` = "Invalid reset link." to model, return `"auth/reset-error"`
      - AlreadyUsed -> add `error` = "This reset link has already been used." to model, return `"auth/reset-error"`

    **SecurityConfig.java** -- Add permitAll for reset password web URLs:

    In the `webFilterChain` method, add these to the `authorizeHttpRequests` section (after the existing `/verify/**` permitAll):
    ```java
    .requestMatchers("/forgot-password").permitAll()
    .requestMatchers("/reset-password").permitAll()
    ```

    The `/change-password` URL does NOT need to be in permitAll -- it requires authentication (covered by `anyRequest().authenticated()`).

    The API URLs (`/api/v1/auth/forgot-password`, `/api/v1/auth/reset-password`, `/api/v1/auth/change-password`) are already covered by the existing `/api/v1/auth/**` permitAll in the apiFilterChain. NOTE: `/api/v1/auth/change-password` is in the API chain's permitAll, but the endpoint itself validates authentication via `Authentication` parameter. If no Bearer token is provided, `Authentication` will be null and the endpoint should return 401. To handle this properly, check `if (authentication == null)` in the controller and return 401, OR better: create a separate request mapping for change-password that is NOT under `/api/v1/auth/` but under `/api/v1/user/` or `/api/v1/account/`.

    ACTUALLY: Keep it simple. The change-password API endpoint is under `/api/v1/auth/` which is permitAll, but the endpoint requires the `Authentication` object. If called without a JWT, `authentication` will be null. Add a null check: if authentication is null, return 401 ResponseEntity. This is simpler than restructuring URL patterns.
