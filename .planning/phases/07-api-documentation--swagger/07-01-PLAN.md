1. Add springdoc-openapi-starter-webmvc-ui dependency to pom.xml:
   ```xml
   <dependency>
       <groupId>org.springdoc</groupId>
       <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
       <version>3.0.1</version>
   </dependency>
   ```
   Place it in the dependencies section alongside other Spring starters.

2. Add springdoc configuration to application.yml AND application.yml.template (keep them in sync):
   ```yaml
   springdoc:
     pathsToMatch: /api/v1/**
     swagger-ui:
       path: /swagger-ui.html
       display-request-duration: true
       operationsSorter: method
       tagsSorter: alpha
   ```
   Add this as a top-level section (same level as `spring:`, `app:`, `server:`).

   The `pathsToMatch: /api/v1/**` is CRITICAL -- it excludes Thymeleaf web controllers (HomeController, AuthWebController, PasswordWebController, AdminWebController, ProfileWebController) from the documentation. Only REST controllers under `/api/v1/` will be documented.

3. **Jackson 3 compatibility check:** After adding the dependency, the application must start. If it fails with `ClassNotFoundException` for Jackson 2 classes (e.g., `com.fasterxml.jackson.databind.node.ObjectNode`), add `spring-boot-jackson2` as a fallback:
   ```xml
   <dependency>
       <groupId>org.springframework.boot</groupId>
       <artifactId>spring-boot-jackson2</artifactId>
   </dependency>
   ```
   Only add this if startup fails. Per research, the official demos work without it.
  </action>

  <action>
1. Create `src/main/java/com/example/usermanagement/shared/config/OpenApiConfig.java`:
   ```java
   package com.example.usermanagement.shared.config;

   import io.swagger.v3.oas.models.Components;
   import io.swagger.v3.oas.models.OpenAPI;
   import io.swagger.v3.oas.models.info.Info;
   import io.swagger.v3.oas.models.security.SecurityRequirement;
   import io.swagger.v3.oas.models.security.SecurityScheme;
   import org.springframework.context.annotation.Bean;
   import org.springframework.context.annotation.Configuration;

   @Configuration
   public class OpenApiConfig {

       @Bean
       public OpenAPI customOpenAPI() {
           final String securitySchemeName = "Bearer Authentication";

           return new OpenAPI()
               .info(new Info()
                   .title("User Management API")
                   .version("1.0.0")
                   .description("REST API for user authentication, profile management, "
                       + "and administration. Use /api/v1/auth/login to obtain a JWT token, "
                       + "then click 'Authorize' and paste the token to access protected endpoints."))
               .addSecurityItem(new SecurityRequirement().addList(securitySchemeName))
               .components(new Components()
                   .addSecuritySchemes(securitySchemeName,
                       new SecurityScheme()
                           .type(SecurityScheme.Type.HTTP)
                           .scheme("bearer")
                           .bearerFormat("JWT")
                           .description("JWT token from /api/v1/auth/login")));
       }
   }
   ```
   Place in shared.config (same as PasswordConfig, AppProperties -- cross-cutting concern per project decision).

2. Update SecurityConfig.webFilterChain to permit Swagger UI paths. In the `authorizeHttpRequests` block, add BEFORE the `.anyRequest().authenticated()` line:
   ```java
   // Swagger UI and OpenAPI spec
   .requestMatchers("/swagger-ui/**", "/swagger-ui.html",
                    "/v3/api-docs/**", "/v3/api-docs.yaml").permitAll()
   ```
   These paths are NOT under `/api/**` so they go in the web chain (Order 2), not the API chain (Order 1). Place them alongside other permitAll entries like `/actuator/health` and `/css/**`.
