  <files>bin/run-dev.sh</files>
  <action>
Create `bin/run-dev.sh` with the following structure, following existing patterns from `bin/env.sh` and `bin/setup.sh`:

1. **Header**: `#!/usr/bin/env bash`, comment describing purpose, `set -euo pipefail`
2. **Path resolution**: `SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"` and `PROJECT_ROOT="$(dirname "$SCRIPT_DIR")"`, then `cd "$PROJECT_ROOT"`
3. **Color helpers**: Same pattern as env.sh — green/red/yellow with terminal detection (`[ -t 1 ]`)
4. **Prerequisite checks**:
   - `command -v java >/dev/null 2>&1` or error "Java is required. Install Java 21+."
   - Check Java version >= 17: parse `java -version 2>&1` output, extract major version
   - Check `./mvnw` exists and is executable, or error "Maven wrapper not found. Run: ./bin/setup.sh"
5. **Environment loading**: `source ./bin/env.sh load` to export .env variables
6. **Template substitution**: `./bin/env.sh substitute-all` to generate config files from templates
7. **Port check**: Read port from `APP_PORT` env var (default 8080). Use `lsof -i ":$PORT" -sTCP:LISTEN` to check if in use. If occupied, print error with suggestion to run `./bin/check-port.sh $PORT go` and exit 1.
8. **Start application**: Print "Starting in dev mode (H2) on port $PORT..." in green, then exec `./mvnw spring-boot:run -Dspring-boot.run.profiles=dev`

Make the file executable: `chmod +x bin/run-dev.sh`

Leave the existing `run-spring-dev-mode.sh` as-is (backward compatibility).

<task type="auto">
  <name>Task 2: Create bin/run-prod.sh Docker Compose launcher</name>
  <files>bin/run-prod.sh</files>
  <action>
Create `bin/run-prod.sh` with the following structure:

1. **Header**: Same as run-dev.sh — shebang, set flags, path resolution, color helpers
2. **Prerequisite checks**:
   - `command -v docker >/dev/null 2>&1` or error "Docker is required. Install Docker Desktop."
   - `docker compose version >/dev/null 2>&1` or error "Docker Compose v2 required. Update Docker Desktop."
   - `docker info >/dev/null 2>&1` or error "Docker daemon is not running. Start Docker Desktop."
3. **Environment loading**: `source ./bin/env.sh load`
4. **Template substitution**: `./bin/env.sh substitute-all`
5. **Command handling**: Support subcommands via `$1`:
   - `up` (default if no arg): `docker compose up --build -d`, then show status with `docker compose ps`, print URLs (app on APP_PORT default 8080, PgAdmin on PGADMIN_PORT default 5050, Swagger UI)
   - `down`: `docker compose down`
   - `logs`: `docker compose logs -f`
   - `status`: `docker compose ps`
   - `restart`: `docker compose down && docker compose up --build -d`
   - Any other arg or `help`: show usage message listing all subcommands
6. **IMPORTANT**: Do NOT export .env variables into the shell environment before running docker compose commands. The compose.yaml is already resolved from the template with actual values. Use `env -i PATH="$PATH" docker compose ...` is NOT needed since compose.yaml already has resolved values (no ${VAR} references). Just run `docker compose` normally — the key point is that the compose.yaml file already contains the resolved values from substitute-all, so Docker Compose does not need .env.

Make executable: `chmod +x bin/run-prod.sh`
  </action>
  <verify>
Run `bash -n bin/run-prod.sh` to check syntax. Run `head -5 bin/run-prod.sh` to confirm shebang and set flags. Run `ls -la bin/run-prod.sh` to confirm executable permission. Run `./bin/run-prod.sh help` to see usage.
  </verify>
  <done>bin/run-prod.sh exists, is executable, passes syntax check, contains: prerequisite checks for Docker/Compose/daemon, env.sh load and substitute-all, subcommand handling (up/down/logs/status/restart/help), and docker compose orchestration.</done>
</task>
