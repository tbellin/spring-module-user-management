<task type="auto">
  <name>Task 1: Create application.yml (common configuration)</name>
  <files>src/main/resources/application.yml</files>
  <action>
Create src/main/resources/application.yml with common configuration shared across all profiles:

```yaml
spring:
  application:
    name: user-management
  jpa:
    open-in-view: false
    hibernate:
      ddl-auto: validate
  flyway:
    enabled: true

server:
  port: ${APP_PORT:8080}

management:
  endpoints:
    web:
      exposure:
        include: health,info
  endpoint:
    health:
      show-details: when-authorized
```

Key settings:
- open-in-view: false (performance best practice - avoids lazy loading in views)
- ddl-auto: validate (Flyway manages schema, Hibernate only validates)
- flyway.enabled: true (migrations run on startup)
- Actuator exposes health endpoint for Docker healthchecks
  </action>
  <verify>
Run: cat src/main/resources/application.yml | grep -E "ddl-auto|flyway"
Expected: Both ddl-auto: validate and flyway: enabled appear
  </verify>
  <done>application.yml exists with common configuration</done>
</task>

<task type="auto">
  <name>Task 2: Create application-dev.yml (H2 configuration)</name>
  <files>src/main/resources/application-dev.yml</files>
  <action>
Create src/main/resources/application-dev.yml for development with H2:

```yaml
spring:
  datasource:
    url: jdbc:h2:mem:userdb;DB_CLOSE_DELAY=-1;MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE;DEFAULT_NULL_ORDERING=HIGH
    driver-class-name: org.h2.Driver
    username: sa
    password:
  h2:
    console:
      enabled: true
      path: /h2-console
  jpa:
    show-sql: true
    properties:
      hibernate:
        format_sql: true
  flyway:
    locations: classpath:db/migration
  docker:
    compose:
      enabled: false
```

CRITICAL H2 URL settings (from RESEARCH.md):
- DB_CLOSE_DELAY=-1: Keep database alive when all connections close
- MODE=PostgreSQL: Enable PostgreSQL compatibility mode
- DATABASE_TO_LOWER=TRUE: Case-insensitive identifiers like PostgreSQL
- DEFAULT_NULL_ORDERING=HIGH: Match PostgreSQL null ordering

Disable Docker Compose integration in dev (we use plain H2).
  </action>
  <verify>
Run: grep "MODE=PostgreSQL" src/main/resources/application-dev.yml
Expected: MODE=PostgreSQL found in H2 URL
  </verify>
  <done>application-dev.yml exists with H2 PostgreSQL compatibility mode</done>
</task>

<task type="auto">
  <name>Task 3: Create application-prod.yml (PostgreSQL configuration)</name>
  <files>src/main/resources/application-prod.yml</files>
  <action>
Create src/main/resources/application-prod.yml for production with PostgreSQL:

```yaml
spring:
  datasource:
    url: jdbc:postgresql://${DB_HOST:localhost}:${DB_PORT:5432}/${DB_NAME:userdb}
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
  jpa:
    show-sql: false
  flyway:
    locations: classpath:db/migration
  docker:
    compose:
      enabled: false
```

Environment variable placeholders:
- ${DB_HOST:localhost} - default to localhost for local testing
- ${DB_PORT:5432} - standard PostgreSQL port
- ${DB_NAME:userdb} - database name
- ${DB_USERNAME} - no default, must be provided
- ${DB_PASSWORD} - no default, must be provided

show-sql: false in production (no SQL logging).
Docker Compose disabled - handled externally by compose.yaml.
  </action>
  <verify>
Run: grep -E "\\\${DB_HOST|\\\${DB_USERNAME}" src/main/resources/application-prod.yml
Expected: Both ${DB_HOST and ${DB_USERNAME found
  </verify>
  <done>application-prod.yml exists with PostgreSQL env var configuration</done>
</task>
