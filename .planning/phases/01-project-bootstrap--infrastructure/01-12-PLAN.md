**Spring Boot vendor-specific migration support:**

Spring Boot auto-configures Flyway with vendor-specific migration support. When `spring.flyway.locations` is set to `classpath:db/migration`, Spring Boot automatically adds `classpath:db/migration/{vendor}` based on the detected database vendor. For H2, the vendor name is `h2`. For PostgreSQL, it is `postgresql`.

This means migrations in `db/migration/h2/` run only with H2, and `db/migration/postgresql/` run only with PostgreSQL. The base `db/migration/` directory is also scanned, so migrations can be shared -- but per CONTEXT.md, we want FULLY INDEPENDENT directories with no shared directory.

**Update Flyway configuration** to use ONLY vendor-specific directories (not the base directory). In `application.yml`, change the flyway locations to use the vendor placeholder:

```yaml
spring:
  flyway:
    enabled: true
    locations: classpath:db/migration/{vendor}
```

The `{vendor}` placeholder is a Spring Boot feature that gets replaced with the detected database vendor name at runtime.

**Create H2 migration** at `src/main/resources/db/migration/h2/V1__init_schema.sql`:

Copy the content of the current `src/main/resources/db/migration/V1__init_schema.sql` as-is. The current SQL was designed to be compatible with both H2 (MODE=PostgreSQL) and PostgreSQL, so it works directly as the H2 version.

```java
package com.example.usermanagement.shared.config;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.boot.context.event.ApplicationReadyEvent;
import org.springframework.context.event.EventListener;
import org.springframework.core.env.Environment;
import org.springframework.stereotype.Component;

import java.io.File;
import java.util.Arrays;

@Component
public class StartupBanner {

    private static final Logger log = LoggerFactory.getLogger(StartupBanner.class);

    private final Environment environment;

    public StartupBanner(Environment environment) {
        this.environment = environment;
    }

    @EventListener(ApplicationReadyEvent.class)
    public void printBanner() {
        String[] activeProfiles = environment.getActiveProfiles();
        boolean isDev = Arrays.asList(activeProfiles).contains("dev");
        boolean isProd = Arrays.asList(activeProfiles).contains("prod");

        log.info("================================================");

        if (isDev) {
            log.info("[DEV MODE] Using H2 in-memory database");
            log.info("  Active profile: dev");

            // Check for .env file
            File envFile = new File(".env");
            if (envFile.exists()) {
                log.info("  .env file: found");
            } else {
                log.info("  .env file: not found");
            }

            // Count generated config files present
            String[] generatedFiles = {
                "compose.yaml", "Dockerfile",
                "src/main/resources/application-dev.yml",
                "src/main/resources/application-prod.yml",
                "docker/pgadmin/servers.json"
            };
            long count = Arrays.stream(generatedFiles)
                    .filter(f -> new File(f).exists())
                    .count();
            log.info("  Generated config files: {}/{}", count, generatedFiles.length);
        } else if (isProd) {
            log.info("[PROD MODE] Using PostgreSQL");
        } else {
            log.info("[UNKNOWN MODE] Active profiles: {}", String.join(", ", activeProfiles));
        }

        log.info("================================================");
    }
}
```

This component:
- Listens for ApplicationReadyEvent (fires after full startup)
- Detects active profile and prints appropriate banner
- In dev mode: shows active profile, .env file status, and generated config file count
- In prod mode: shows PostgreSQL message
- Uses SLF4J logging (consistent with Spring Boot)

Place it in the `shared.config` subpackage (alongside SecurityConfig, per 01-04 decision).

Create a schema comparison test that verifies dev (H2) and prod (PostgreSQL) migrations produce the same table structures. This test runs as part of the regular `mvn test` suite.

**Approach:** Since we don't have a live PostgreSQL instance during testing, and H2 runs in PostgreSQL compatibility mode, the test strategy is:

1. Parse both migration SQL files (h2/V1__init_schema.sql and postgresql/V1__init_schema.sql)
2. Extract table definitions (CREATE TABLE statements) and compare structural elements
3. Verify same tables, columns, and constraints exist in both

Implementation at `src/test/java/com/example/usermanagement/SchemaComparisonTests.java`:

```java
package com.example.usermanagement;

import org.junit.jupiter.api.Test;
import org.springframework.core.io.ClassPathResource;

import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.Set;
import java.util.TreeSet;
import java.util.regex.Matcher;
import java.util.regex.Pattern;

import static org.junit.jupiter.api.Assertions.*;

/**
 * Verifies that H2 (dev) and PostgreSQL (prod) Flyway migrations
 * produce structurally equivalent schemas.
 *
 * This test parses migration SQL files and compares:
 * - Table names (CREATE TABLE)
 * - Version numbers and filenames match across vendors
 */
class SchemaComparisonTests {

    @Test
    void devAndProdMigrationsShouldHaveSameVersions() throws IOException {
        // List migration files in each vendor directory
        Path h2Dir = new ClassPathResource("db/migration/h2").getFile().toPath();
        Path pgDir = new ClassPathResource("db/migration/postgresql").getFile().toPath();

        Set<String> h2Files = new TreeSet<>();
        Set<String> pgFiles = new TreeSet<>();

        Files.list(h2Dir)
                .filter(p -> p.getFileName().toString().endsWith(".sql"))
                .filter(p -> p.getFileName().toString().startsWith("V"))
                .forEach(p -> h2Files.add(p.getFileName().toString()));

        Files.list(pgDir)
                .filter(p -> p.getFileName().toString().endsWith(".sql"))
                .filter(p -> p.getFileName().toString().startsWith("V"))
                .forEach(p -> pgFiles.add(p.getFileName().toString()));

        // V2__seed_dev_data.sql is dev-only, so filter to V1 (structural migrations)
        Set<String> h2Structural = new TreeSet<>();
        Set<String> pgStructural = new TreeSet<>();

        for (String f : h2Files) {
            if (isStructuralMigration(f)) {
                h2Structural.add(f);
            }
        }
        for (String f : pgFiles) {
            if (isStructuralMigration(f)) {
                pgStructural.add(f);
            }
        }

        assertEquals(pgStructural, h2Structural,
                "Structural migration files should have same names in h2/ and postgresql/ directories");
    }

    @Test
    void v1MigrationsShouldCreateSameTables() throws IOException {
        String h2Sql = readMigration("db/migration/h2/V1__init_schema.sql");
        String pgSql = readMigration("db/migration/postgresql/V1__init_schema.sql");

        Set<String> h2Tables = extractTableNames(h2Sql);
        Set<String> pgTables = extractTableNames(pgSql);

        assertFalse(h2Tables.isEmpty(), "H2 migration should create at least one table");
        assertFalse(pgTables.isEmpty(), "PostgreSQL migration should create at least one table");

        assertEquals(pgTables, h2Tables,
                "H2 and PostgreSQL V1 migrations should create the same tables");
    }

    private String readMigration(String classpath) throws IOException {
        ClassPathResource resource = new ClassPathResource(classpath);
        return new String(resource.getInputStream().readAllBytes(), StandardCharsets.UTF_8);
    }

    private Set<String> extractTableNames(String sql) {
        Set<String> tables = new TreeSet<>(String.CASE_INSENSITIVE_ORDER);
        // Match CREATE TABLE [IF NOT EXISTS] table_name
        Pattern pattern = Pattern.compile(
                "CREATE\\s+TABLE\\s+(?:IF\\s+NOT\\s+EXISTS\\s+)?(\\w+)",
                Pattern.CASE_INSENSITIVE);
        Matcher matcher = pattern.matcher(sql);
        while (matcher.find()) {
            tables.add(matcher.group(1).toLowerCase());
        }
        return tables;
    }

    private boolean isStructuralMigration(String filename) {
        // Structural migrations create/alter schema. Seed data migrations are not structural.
        // Convention: seed migrations contain "seed" in the name
        return !filename.toLowerCase().contains("seed");
    }
}
```

Key design decisions:
- **No @SpringBootTest**: This is a plain unit test (fast, no Spring context needed) -- consistent with ModularityTests pattern from 01-08.
- **Structural vs seed filtering**: V2__seed_dev_data.sql is dev-only and excluded from comparison (it's a seed migration, not structural).
- **Table name comparison**: Extracts CREATE TABLE names from SQL and compares sets. This catches the most critical divergence (missing tables).
- **Case-insensitive**: H2 may uppercase table names; comparison is case-insensitive.
