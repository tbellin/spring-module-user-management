  <action>
    Follow the established test patterns from PasswordApiTest and PasswordWebTest. Use `@SpringBootTest`, `@AutoConfigureMockMvc`, `@ActiveProfiles("dev")`. MockBean `JavaMailSender` to prevent SMTP calls. Use `SecurityMockMvcRequestPostProcessors.user()` for API chain tests and `.with(csrf())` for web chain POST tests.

    **1. ProfileApiTest.java** (package: `com.example.usermanagement.user`)
    - Test: GET /api/v1/users/me with authenticated user returns 200 + user JSON (email, roles, createdAt present)
    - Test: GET /api/v1/users/me without authentication returns 401
    - Test: PUT /api/v1/users/me with valid body returns 200 + updated user JSON
    - Test: PUT /api/v1/users/me without authentication returns 401
    - Use `.with(user("testuser@example.com").roles("USER"))` for authenticated requests
    - Note: These tests hit the API filter chain (stateless, JWT) so use SecurityMockMvcRequestPostProcessors

    **2. ProfileWebTest.java** (package: `com.example.usermanagement.user`)
    - Test: GET /profile when authenticated returns 200 with profile page content
    - Test: GET /profile when anonymous redirects to /login
    - Test: POST /profile with valid params redirects to /profile (303 or 302)
    - Use `@WithMockUser` or `.with(user(...))` for web chain tests
    - Use `.with(csrf())` for POST requests

    **3. AdminApiTest.java** (package: `com.example.usermanagement.auth`)
    - Test: GET /api/v1/admin/users with ADMIN role returns 200 + paginated JSON
    - Test: GET /api/v1/admin/users with USER role returns 403
    - Test: GET /api/v1/admin/users without auth returns 401
    - Test: POST /api/v1/admin/users with ADMIN role and valid body returns 201 (MockBean JavaMailSender to avoid actual email)
    - Test: POST /api/v1/admin/users with duplicate email returns 409
    - Test: PUT /api/v1/admin/users/{id} with ADMIN role and valid body returns 200
    - Test: PATCH /api/v1/admin/users/{id}/status with ADMIN role returns 200
    - Test: PATCH /api/v1/admin/users/{id}/status self-disable returns 400
    - Use `.with(user("admin@example.com").roles("ADMIN"))` for admin requests
    - Use `.with(user("user@example.com").roles("USER"))` for non-admin requests
    - For create/update tests that need existing users: use `@Sql` to seed test data or use the UserService/UserRepository directly via `@Autowired`

    **4. AdminWebTest.java** (package: `com.example.usermanagement.auth`)
    - Test: GET /admin/users with ADMIN returns 200 with admin page content
    - Test: GET /admin/users with USER role returns 403
    - Test: GET /admin/users anonymous redirects to login
    - Test: GET /admin/users/new with ADMIN returns 200 with create form
    - Test: POST /admin/users/new with ADMIN and valid params redirects to /admin/users
    - Use `.with(csrf())` for POST requests

    **General test setup patterns:**
    - Use `@Autowired MockMvc mockMvc`
    - Use `@MockBean JavaMailSender javaMailSender` to prevent SMTP failures
    - Use UUID-based unique test emails for isolation: `String email = UUID.randomUUID() + "@test.com"`
    - For admin tests needing existing users: create a test user via UserService or UserRepository in a `@BeforeEach` method, then use that user's ID in test requests
    - Use Jackson 3 `JsonMapper` for serializing request bodies (consistent with Phase 3-5 test patterns)
    - When testing with the dev profile, a seed user (tiziano@example.com with ADMIN role) exists from Flyway seed data

    **Key assertions:**
    - Profile GET response contains "email", "roles", "createdAt" fields
    - Admin list response contains "content" (paginated), "totalElements", "pageable"
    - 403 responses use appropriate error format (JSON for API, error page for web)
    - Create user returns 201 with user DTO containing the specified role
    - Self-disable returns 400 with error message
