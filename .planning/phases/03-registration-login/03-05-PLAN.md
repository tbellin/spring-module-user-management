<task type="checkpoint:human-verify" gate="blocking">
  <what-built>
    Complete registration and login system with:
    - REST API endpoints: POST /api/v1/auth/register, POST /api/v1/auth/login
    - Web pages: /login, /register with Bootstrap 5 styling
    - Toast notifications for success feedback
    - Password show/hide toggle
    - Remember-me functionality
    - Auto-login after registration
    - Proper error handling and validation
  </what-built>
  <how-to-verify>
    Start the application in dev mode:
    ```bash
    ./mvnw spring-boot:run -Dspring-boot.run.profiles=dev
    ```

    **Web UI Tests (visit http://localhost:8080):**

    1. **Home Page (Anonymous):**
       - [ ] Home page loads with nav showing "Login" and "Register" links
       - [ ] No "Logout" button visible

    2. **Registration Flow:**
       - [ ] Click "Register" - registration form appears
       - [ ] Try submitting empty form - validation errors appear at top
       - [ ] Enter email: test@example.com, display name: Test User, password: password123
       - [ ] Click password toggle - password becomes visible, button changes to "Hide"
       - [ ] Submit form
       - [ ] Redirected to home page
       - [ ] Toast notification appears: "Welcome! Your account has been created."
       - [ ] Nav now shows "Logout" button (authenticated)

    3. **Logout Flow:**
       - [ ] Click "Logout" button in nav
       - [ ] Redirected to /login?logout
       - [ ] Message: "You have been logged out."

    4. **Login Flow:**
       - [ ] Enter email: test@example.com, password: password123
       - [ ] Submit form
       - [ ] Redirected to home page
       - [ ] Nav shows "Logout" (authenticated)

    5. **Remember Me:**
       - [ ] Logout
       - [ ] Login with "Remember me" checked
       - [ ] Close browser, reopen, visit http://localhost:8080
       - [ ] Should still be logged in (session persists)

    6. **Error Handling:**
       - [ ] Logout and try login with wrong password
       - [ ] Error message: "Invalid email or password." (generic, no enumeration)
       - [ ] Try registering with test@example.com again
       - [ ] Error: "An account with this email already exists"

    **API Tests (use cURL or similar):**

    7. **API Registration:**
       ```bash
       curl -X POST http://localhost:8080/api/v1/auth/register \
         -H "Content-Type: application/json" \
         -d '{"email":"api@example.com","password":"password123","displayName":"API User"}'
       ```
       - [ ] Returns 201 with JSON containing token, email, displayName, roles

    8. **API Login:**
       ```bash
       curl -X POST http://localhost:8080/api/v1/auth/login \
         -H "Content-Type: application/json" \
         -d '{"email":"api@example.com","password":"password123","rememberMe":false}'
       ```
       - [ ] Returns 200 with JSON containing token

    9. **API with Remember-Me:**
       ```bash
       curl -X POST http://localhost:8080/api/v1/auth/login \
         -H "Content-Type: application/json" \
         -d '{"email":"api@example.com","password":"password123","rememberMe":true}'
       ```
       - [ ] expiresIn value is larger than without rememberMe

    10. **Use JWT for Protected Request:**
        ```bash
        # Get token
        TOKEN=$(curl -s -X POST http://localhost:8080/api/v1/auth/login \
          -H "Content-Type: application/json" \
          -d '{"email":"api@example.com","password":"password123","rememberMe":false}' | jq -r '.token')

        # Use token (should get 404 for non-existent endpoint, not 401)
        curl -H "Authorization: Bearer $TOKEN" http://localhost:8080/api/users
        ```
        - [ ] Returns 404 (not 401) - proves authentication worked
  </how-to-verify>
